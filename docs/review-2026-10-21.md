# geoask 代码审查报告

- 日期：2026-10-21
- 范围：`geoask.py`、`geoask_service.py`、`geoask_gui.py`、`geoask_map.py`、`geoask_routing.py`、`geoask_location.py`、`geoask_parking.py`、`geoask_places.py`、`geoask_data.py`、`tests/`、`scripts/`、配置/打包/文档
- 方式：只读审查 + 本地复现（真实缓存嵌入模型、真实 OSM 数据、`route-probe.json`、无头 Tk 探针、coverage、ruff），未修改任何项目源码/配置/数据
- 基线：`.venv\Scripts\python.exe -m pytest -q` → **80 passed, 1 skipped**；`GEOASK_MODEL_TESTS=1` → 81 passed

## 总体结论

项目的核心设计质量高于一般个人项目：LLM 只出意图、SQL 全参数化、类别由本地嵌入+阈值判定、距离用椭球米制、数据带 manifest 和哈希、密钥不落盘、GUI 后台线程不直接碰 Tk。审查确认这些关键设计基本都实现正确。

但存在 **6 个高优先级问题**（其中 2 个是每个用户都会遇到的界面/导航错误，1 个是安装包不可用），以及一组会误导用户或让测试“绿而不实”的中等问题。没有发现会破坏数据或任意执行代码的漏洞。

建议修复顺序见文末。

## 一、高优先级

### 1. 模糊名称查询后，地图缩放到最大级，所有候选地点都在屏幕外
- 位置：`geoask_gui.py:799-807`，`geoask_map.py:83-97`
- 复现：查询“去星巴克”。本地数据中“星巴克”有 **177 个同名地点**，服务层正确地要求用户选择（`selected_index=None`），但 `_show_result` 用 `points = [起点, *已选站点]` 调 `fit`；没有已选站点时只有一个点，`SlippyMap.fit` 在 zoom 18 立即“命中”，于是地图停在起点最大放大级，10 个候选（距起点 786–1487 m）全部在视口外。状态栏还显示“地点选择已完成”。
- 影响：链式品牌名（星巴克、麦当劳、全家等）是极常见的查询，用户会以为地图坏了；候选列表在另一个 Tab，很难发现。
- 建议：
  - fit 时把当前站（或所有站）的候选坐标一并纳入；
  - 单点时不要 `fit` 到 18 级，限制在 14–16 级；
  - 未全选时状态栏改为“请选择具体地点”，可自动切到“候选地点”Tab；
  - 为“同名多结果”加一条 GUI 回归测试（下面测试部分）。

### 2. GUI 事件轮询任一处理器抛异常 → 永久冻结，且 pythonw 下无任何提示
- 位置：`geoask_gui.py:674-755`
- 机制：`_poll` 只有 `except Empty`，`self.after(80, self._poll)` 在函数末尾。任一事件处理器（`_show_result`、`_load_config`、`messagebox`、停车场/定位处理器等）抛异常，后续 `after` 不会再注册；`busy` 保持 `True`，进度条继续转，所有按钮/下拉框保持禁用。README 推荐用 `pythonw.exe`，stderr 不可见。
- 验证：注入一个让 `_show_result` 抛异常的事件后，后续事件不再出队，`busy` 一直为 True。
- 建议：每个事件包 `try/except Exception`，记录 traceback 并在状态栏/对话框提示“界面内部错误”，`after` 放进 `finally`；重写 `report_callback_exception` 写入日志文件。

### 3. 非 editable 安装后，`geoask` / `geoask-gui` 入口不可用
- 位置：`pyproject.toml:18-19`、`geoask.py:19`、`geoask.py:474-475`、`geoask_location.py:46`、`geoask.egg-info/SOURCES.txt`
- 证据：`pyproject.toml` 只声明 `py-modules`，没有 package-data/data-files；`SOURCES.txt` 不含 `config.yaml`、`data/`、`scripts/`。代码却从 `ROOT`（模块所在目录）读取默认配置、数据和 PowerShell 定位脚本。
- 影响：`pip install .` 后 `geoask` 会在读取 `site-packages/config.yaml` 时失败；`geoask-gui` 同样；设备定位脚本缺失。只有 README 快速开始里的 `-e .`（editable）能工作，但 README:7 宣称“安装项目后也可使用 `geoask-gui` 命令”。
- 建议：把配置/数据/脚本作为 package data 一起打包，用 `importlib.resources` 定位；增加“构建 wheel → 在干净临时环境安装 → 跑 `geoask --help` 和一次 demo 查询”的打包冒烟测试。若暂不打包，至少在安装模式下给出明确错误，并把 README 改为“仅支持源码/editable 运行”。

### 4. 路线请求把 `language`/`units` 放在 Valhalla 顶层，分段导航永远是英文
- 位置：`geoask_routing.py:89-93`
- 证据：抓包文件 `.downloads/route-probe.json` 中 `trip.language == "en-US"`、`trip.units == "kilometers"`，maneuvers 为 `Walk east on 呼家楼西里南街.`、`Turn left.`；GUI 原样展示。Valhalla 要求这两个字段在 `directions_options` 下，顶层字段被忽略。
- 影响：所有道路路线的转向提示都是英文，与中文界面不一致。
- 建议：
  ```python
  payload = {..., "directions_options": {"language": "zh-CN", "units": "kilometers"}}
  ```
  并在 `test_route_api_uses_real_mode_and_preserves_waypoints` 里断言请求 JSON 的 `directions_options`，而不只是 `costing`/`locations`。

### 5. Python 3.10（项目声明的最低版本）上，设备定位 100% 失败
- 位置：`geoask_location.py:29-31`、`scripts/get_location.ps1:26`
- 机制：PowerShell 的 `ToString('o')` 输出 **7 位**小数秒（如 `2026-10-21T10:39:50.2773631+00:00`），Python 3.11+ 的 `fromisoformat` 能接受，3.10 及更早只接受 3/6 位小数秒。本机 Python 3.9 验证会抛 `ValueError: Invalid isoformat string`。
- 影响：`pyproject.toml`/README 宣称 Python 3.10+，但 3.10 用户永远收到“设备返回的位置无效或超过五分钟”，且现有测试只用 Python `isoformat()` 的 6 位格式，测不出来。
- 建议：解析前截断到 6 位（`re.sub(r"(\.\d{6})\d+", r"\1", ts)`），或让 PowerShell 输出 `ToString("yyyy-MM-dd'T'HH:mm:ss.fffK")`；增加 7 位小数秒的回归测试。同时把 `requires-python` 与 lock/依赖真实支持范围对齐（见 7）。

### 6. “附近停车场”被语义映射成 `park`（公园），静默返回错误类别
- 位置：`geoask.py:390-399`（`SemanticMapper.match`），默认数据类别 `cafe/fitness_centre/park/railway_station/restaurant/supermarket`
- 证据（真实缓存模型）：`match("停车场") → park, similarity 0.662, margin 0.258`，被接受；`match("停车位") → park 0.642` 也被接受；而 `match("火锅") → restaurant 0.477` 会被拒绝。默认 POI 文件没有停车类别，因此用户不勾选停车场模式、直接问“附近停车场”时会得到公园列表。
- 影响：用户得到看似合理但语义错误的结果；与 README 中“停车场由独立目录/停车模式提供”的说明不一致。
- 建议任选：
  - 在 `SemanticMapper.match` 前对“停车/停车场/车位”等意图特殊处理：提示“请勾选‘驾车到最后一站附近停车场’或使用停车查询”，而不是模糊接受 `park`；
  - 或把 parking 类别加入附近样例数据，让映射有正确目标；
  - 或在阈值判定中加入“最佳类别与意图词明显矛盾”的保护（例如要求意图词共现，成本较高，不推荐作为唯一方案）。

## 二、中优先级（正确性 / 健壮性）

### 7. 依赖与 Python 版本契约自相矛盾
- 位置：`pyproject.toml:9`（`requires-python = ">=3.10"`）、`requirements.lock.txt:1/10/26`、`requirements.txt:7`
- 证据：lock 中 `onnxruntime 1.31.0`、`filelock 4.2.4`、`httpcore2/httpx2` 的 `Requires-Python >= 3.11`，所以 `pip install -r requirements.lock.txt` 在 3.10 上装不起来；`fastembed 0.9.0` 在 Python ≥3.14 时需要 `numpy>=2.3.0`，但 `requirements.txt` 锁 `numpy==2.2.6`。项目没有 CI。
- 建议：把 `requires-python` 收紧到实际验证过的范围（例如 `>=3.11,<3.14`），或为不同版本加 markers；lock 标注“Python 3.13/Windows 专用”；在 CI 跑 3.10/3.13（以及声明支持的 3.14）矩阵。

### 8. 类别向量缓存损坏时崩溃，而不是自动重建
- 位置：`geoask.py:371-379`
- 证据：
  - 零字节 `categories-*.npy` → `np.load` 抛 `EOFError`，不在 `(OSError, ValueError, TypeError, GeoaskError)` 里，CLI 只打印 `Aborted!`；
  - zip 内容 → `BadZipFile`；可读 zip 返回 `NpzFile` → `vectors.ndim` 抛 `AttributeError`；
  - 只有 `shape[0]` 校验，若缓存维度与模型不一致，会在 `self.vectors @ vector` 处炸出 `matmul ... size 3 is different from 7`。
- 建议：`try/except Exception` 视为缓存 miss；校验 dtype、finite、`shape[1]`；写缓存用唯一临时名 + `os.replace`，失败时保留旧缓存；增加零字节/zip/错误维度测试。

### 9. 字段映射大小写敏感，合法数据被误判“字段不存在”
- 位置：`geoask.py:176-193`
- 证据：GeoJSON 属性名 `Name`/`Category`，配置 `name: name` / `category: category` → `字段映射不存在: ['category','name']`；而 DuckDB `SELECT "name" FROM ST_Read(...)` 实际可以解析到 `Name`（DuckDB 标识符大小写不敏感）。
- 影响：QGIS/部分导出工具产生首字母大写字段时，GUI 导入失败；这是“换自己的数据”主路径。
- 建议：用 `{c.lower(): c for c in cols}` 做大小写不敏感解析，再用实际列名拼表达式；`field_mapping.aliases` 和 `place_catalog_field_mapping` 同样处理；加回归测试。

### 10. 空别名被当成非空，绕过导入的名称校验并虚增“有名称”计数
- 位置：`geoask.py:188-194`、`geoask_data.py:29-34`
- 证据：`regexp_split_to_array(coalesce(CAST(NULL AS VARCHAR), ''), '[;；|]')` 返回 `['']`，于是 `len(aliases)>0` 为真；`title: ""` + `alt_name: ""` 的数据能通过 `import_region` 并保存配置，返回的“有名称/别名”计数为 1（实际 0）。README:168 承诺“验证数据、坐标和字段后才保存”。
- 建议：`list_filter(regexp_split_to_array(...), x -> coalesce(trim(x),'') <> '')`；`geoask_data` 用 `len(list_filter(aliases, ...))>0`；为“名称为空但别名列为空”的数据加导入测试。

### 11. LLM 的“不明确”哨兵没有被特殊处理，自定义数据下会静默返回无关地点
- 位置：`geoask.py:241/301`（提示词要求“不明确”）、`geoask.py:390-399`、`geoask_service.py:196-223`
- 证据：自定义类别词表含 `unknown`/`未知` 时，`match("不明确")` 被接受（相似度 0.74–0.92），端到端“今天天气怎么样”会返回并自动选中一个 POI。默认北京词表下“不明确”相似度只有 0.24，会被拒绝，所以本地测试发现不了。
- 建议：在 `match` 或 `parse_intent/parse_plan` 里显式识别哨兵，直接拒绝并提示无法识别地点需求；加“类别词表含 unknown/未知”的测试。

### 12. 地图瓦片：缓存写入失败会丢弃已下载瓦片并误报网络故障
- 位置：`geoask_map.py:225-239`
- 机制：`mkdir/write_bytes/replace` 与 `completed.put((key, data))` 在同一个 `try` 内；缓存目录只读/磁盘满/杀软锁住时，异常直接走 `except`，发出的却是 `completed.put((key, None))`。地图显示占位块和“底图暂不可用”，45 秒后重试，反复浪费流量。
- 验证：patch `Path.write_bytes` 抛 `OSError`，已下载并通过校验的 256×256 PNG 仍被报告为失败。
- 建议：先 `completed.put((key, data))` 再尽力写缓存（缓存失败 `except OSError: pass` 并可记一次警告）；只有下载/解码失败才报告。

### 13. 地图 `_poll` 无异常保护，一个坏图会让底图永久停止更新
- 位置：`geoask_map.py:241-266`
- 机制：`Image.open/convert/ImageTk.PhotoImage` 在 `try` 外，且 `after` 在末尾；JPEG（`verify()` 对 JPEG 基本不校验）、截断图或 TclError 会让轮询停止。与界面 `_poll` 是同一类问题。
- 建议：逐项 `try/except Exception`，标记 `failed[key]` 后继续；`after` 放 `finally`。

### 14. 区域配置保存用硬链接，FAT/exFAT/SMB 上失败且抛原始 OSError
- 位置：`geoask_data.py:40-49`
- 证据：`os.link` 在 exFAT/FAT32/部分 SMB 共享上不支持；patch 后 GUI 显示 `PermissionError [Errno 1] Incorrect function: ...yaml`。另外 `temporary.unlink()` 在 finally 中失败可能“已保存却报失败”。
- 建议：`os.link` 失败时回退到 `open(dest, "xb") + write` 或“写入临时文件 + 原子 replace（先复查不存在）”；清理改为 best-effort；统一转成 `GeoaskError`。

### 15. 设置对话框两个 Apply 互相丢弃未保存内容（包括刚输入的 API Key）
- 位置：`geoask_gui.py:487-530`、`532-564`
- 机制：LLM Tab 的“应用设置”只读取 LLM 字段并 `dialog.destroy()`；地图 Tab 的“应用地图与路径设置”只读取地图字段并销毁窗口。用户在 LLM Tab 输入 Key 后点了地图 Tab 的 Apply，Key 不会被保存，下一次查询又提示“尚未设置密钥”。
- 建议：单一 Apply 统一读取两个 Tab；或各 Apply 都先应用双方字段再关闭；至少在存在未保存修改时提示。

### 16. 查询/换点失败后，旧站点下拉框仍可交互，与 `result=None` 不一致
- 位置：`geoask_gui.py:577-612`、`627-628`、`745-752`
- 证据：把 `config_path` 指向不存在的 YAML 跑双站 demo，失败后 `result is None`，但两个旧站点 combobox 仍是 `readonly`，改选只改显示、无任何效果（`reselect_stop` 直接 return），状态栏仍是“查询未完成”。
- 建议：查询开始或收到 error 事件时销毁/禁用 `stop_controls` 并清空 `result_subtitle`。

### 17. 瓦片磁盘缓存“七天”只控制重新下载，从不删除；磁盘无限增长
- 位置：`geoask_map.py:211-231`
- 说明：README 的“磁盘缓存七天”容易被理解为保留 7 天；实际缓存文件永久保留，只有再次请求到过期 tile 才刷新。
- 建议：启动时按 mtime/总大小做一次清理，或每周后台 prune；同时在 README 改为“缓存内容 7 天后过期，文件不自动删除”。

### 18. 名称归一化在 Python 与 DuckDB 中不一致（全角空格等）
- 位置：`geoask_places.py:9-10`（Python `re` 的 `\s` 是 Unicode 感知） vs `38-41`（DuckDB/RE2 的 `\s` 仅 ASCII）
- 证据：数据中 `"国家\u3000体育场"` 的 `name_key` 保留全角空格，而查询“国家体育场”去掉了空格，永远匹配不上。
- 建议：只实现一套归一化（DuckDB `create_function` 调 Python，或 SQL 里显式列出 `[\\s\\x{00a0}\\x{3000}]+`）；加全角空格/NBSP 测试。

### 19. `_prepare` 的缓存失效判断与重载策略
- 位置：`geoask_service.py:100-113`
- 说明：只用 `mtime_ns + size`，内容变了而这两者不变（保留时间戳的复制/同步工具）会继续用旧 DuckDB 数据和旧 `named_places`；`catalog.stat()` 在同一表达式里调两次有 TOCTOU；而 `settings.model_dump_json(exclude={"llm"})` 让只改 map/parking/cache 的配置也触发整份数据+模型重载。
- 建议：单次 stat；用内容哈希（或 inode+size+mtime）；签名只包含数据/目录/嵌入模型/阈值/别名相关字段。

### 20. 停车场候选被通用 limit 截断，且大量“未命名停车场”难以区分
- 位置：`geoask_parking.py:27-34`
- 说明：默认 `limit=10`，鸟巢 1000 m 内 10 条候选里 8 条显示为“未命名停车场”，只能靠距离区分；5000 m 时直接截断也不提示还有更多。
- 建议：停车场用独立的 limit（或“显示更多”），命名排序时优先有名称的停车场；保留 `osm_id` 做稳定去重。

### 21. CLI 失败仍返回退出码 0；名称查询路径不校验 `--radius`
- 位置：`geoask.py:526-540`、`477-487`、`491-503`
- 证据：类别映射被拒绝、无结果、名称候选待确认都只打印文本，退出码 0；`geoask "…鸟巢…" --radius nan` 在名称分支可成功退出（该分支根本没走 `build_query`）。类别分支的 `build_query` 也不是完全没有漏洞：`bool` 半径会当 `True→1` 处理（`geoask.py:426`）。
- 建议：对“最终没有可用结果”用 `ctx.exit(1)`/`ClickException`；两个分支都先调用参数校验（`build_query` 或独立校验函数）；`build_query` 拒绝 bool。

### 22. `parse_intent` 自建的 OpenAI 客户端未关闭
- 位置：`geoask.py:251-257` vs `311-312`
- 说明：`parse_plan` 用 `with OpenAI(...) as owned`，`parse_intent` 直接创建客户端且不 `close()`；使用环境变量 Key（无会话 Key）的 GUI 查询每次泄漏一个 httpx 连接池，直到 GC。
- 建议：与 `parse_plan` 一致，`with ... as owned: return parse_intent(query, settings, owned)`。

## 三、低优先级 / 打磨项

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 23 | `geoask.py:270/324`、`:38` | 要求 `finish_reason == "stop"`；部分 OpenAI 兼容代理返回 `None`；`travel_mode` 必填但提示词说默认 walking | 只拒绝 `length`/`content_filter`；`travel_mode` 默认 `walking` |
| 24 | `geoask.py:138-150` | `read_settings` 不捕获 `UnicodeDecodeError`（GBK 配置会让 GUI 启动回调报错）；false-y YAML 根被当成 `{}`；路径解析在 `try` 外；不展开 `~` | 统一转 `GeoaskError`；要求 mapping 根；`expanduser()` |
| 25 | `geoask.py:213-218` | 无效坐标检查：`NOT (isfinite(ST_X)...)` 对 NULL 结果为 NULL，NULL 坐标行不被计数 | 显式 `geometry IS NULL OR NOT (...)` |
| 26 | `geoask_places.py:53-56` | `place_aliases` 只按 alias 目标查，目标过期/拼错时原始名称也不兜底；空 alias 值直接无结果 | 加载时校验别名；原始名称作为低优先级 fallback |

### 建议补充的测试（按性价比排序）
1. **GUI 控制器无头测试**：把队列事件派发/状态机从 Tk 中抽出，用假 widget 或 headless root 测试：
   - `_poll` 处理器异常后仍继续轮询；

   - `close()` 幂等、busy 时关闭不卡死。
2. **瓦片缓存纯函数化测试**：注入 opener/clock/temp dir，覆盖命中、过期、损坏缓存、超限、非 256×256、失败退避、generation 丢弃、队列满、LRU、close；并覆盖“缓存写失败仍显示瓦片”。
3. **LLM 边界**：json_object 与 structured 两种模式下的非法 JSON、额外字段、空意图、refusal、`finish_reason=length/None`、`parsed=None`、`OpenAIError`/超时，且断言不回显 provider 内容/密钥。
4. **缓存损坏**：零字节、zip、错误维度 npy。
5. **导入**：大写字段名、全空名称+空别名、`os.link` 失败回退、无效 CRS/坐标、目标已存在、模型/API 未被调用、不写入密钥。

### 工程建议
- **用 manifest 代替硬编码快照**：`tests/test_gui_service.py:32` 的 415、`test_named_places.py:55-56` 的精确鸟巢坐标、`test_travel.py:78` 的真实候选索引 2，都应读 `data/manifest.json` / `data/places-manifest.json`，或改成断言“关系/排名/数量范围”；否则合法数据刷新会让测试变红，而坏数据（例如 250 行）仍可能通过。
- **CI**：至少 Windows + `pytest`；加 Python 3.10/3.13/3.14 矩阵；wheel 构建 + 安装冒烟测试；`ruff`（配置在 `pyproject.toml`，排除中文标点误报 RUF001/RUF002）；可选 `mypy`/`pyright` 只对核心模块。当前仓库甚至没有 `.git`，建议先 `git init` 提交基线再改。
- **可观测性**：GUI/workThread 的异常写滚动日志（`%LOCALAPPDATA%\geoask\logs`），状态栏只显示摘要；不要 `except Exception: pass`。
- **请求代际**：给 `QueryRequest`/job/event 加单调递增 ID，丢弃过期结果；目前靠单飞 `busy` 保证，未来加“取消查询/并发预取”时会立即出问题。
- **原子写**：CSV、配置、瓦片统一临时文件 + 原子替换；瓦片临时名带 pid/uuid，避免两个实例/两次 generation 共用 `.partial` 互相覆盖。
- **缓存治理**：瓦片按 mtime/大小定期清理；尊重 `ETag/Cache-Control`（可选）；嵌入缓存加入依赖版本和预处理标识。
- **数据契约**：为自定义数据加 `schema_version`；导入时提示停车类别、CRS、图层；对“无类别”数据明确禁用附近类别查询（目前会提示，但错误文案可统一）。
- **UI 文案**：统一中文错误（经纬度、半径、结果数、接口错误）；错误发生时不要保留“上一程”的交互控件。
