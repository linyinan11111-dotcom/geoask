# geoask 项目代码结构与技术架构详解

当前产品是本机桌面应用：DeepSeek（或兼容接口）只负责把一句话解析成行程意图，高德 Web 服务负责地点、停车场和步行/骑行/驾车路线，界面是 `web/` 里的 HTML，由 `geoask_web.py` 放在 pywebview 窗口中。

地点查询和道路规划不读取本地 OSM、GeoPackage 或嵌入模型，也不调用 Valhalla。配置里如果还留着这些旧字段，读取时会被忽略；`amap.enabled` 与 `amap.primary` 必须为 true。

## 1. 从一句话到路线

```text
用户输入 + 起点
    → geoask_web.WebApp
    → geoask_service.QueryEngine
    → DeepSeek 解析 GeoPlan（最多 6 站）
    → 高德 place/text 按顺序检索每一站
    → 用户确认候选
    → 高德步行 / 骑行 / 驾车路线
    → 地图折线、分段说明、可选终点停车场、CSV
```

坐标在程序内部使用 WGS84。调用高德时转换成 GCJ-02，返回的地点和折线再转回 WGS84，供距离和地图标记使用。

## 2. 目录

```text
geoask.py                 配置、意图模型、DeepSeek 解析、命令行
geoask_service.py         多站查询、换点、停车场编排
geoask_amap.py            高德 POI 与路线，含 WGS84/GCJ-02 转换
geoask_web.py             本机 HTTP 服务与 pywebview 桌面窗口
geoask_parking.py         用停车场替换最后一站的驾车终点
geoask_routing.py         路线结果数据结构
geoask_location.py        Windows 设备定位
geoask_credentials.py     本机接口设置与密钥保存
geoask_runtime.py         日志与原子写文件
geoask_resources/         安装后的配置、网页和定位脚本
web/                      HTML / CSS / JavaScript 界面与 Lens 光学组件
config.yaml               默认起点、底图、高德与 DeepSeek 参数
scripts/build_desktop.py  Windows 便携包
scripts/desktop_entry.py  冻结程序入口
scripts/get_location.ps1  Windows 定位桥接
启动界面.cmd              Windows 源码双击入口
```

`geoask-gui` 命令启动的是 `geoask_web:main`，也就是当前的 HTML 桌面窗口。

## 3. 各层职责

| 层 | 文件 | 做什么 |
| --- | --- | --- |
| 界面 | `web/`、`geoask_web.py`、`启动界面.cmd` | 地图、选点、路线、接口设置；只接受本机请求 |
| 行程 | `geoask_service.py` | 按顺序查站、换点后重查后续站、查找停车场 |
| 意图 | `geoask.py` | Pydantic 校验 DeepSeek JSON，不执行查询 |
| 地图服务 | `geoask_amap.py` | 地点检索与真实道路路线 |
| 凭据 | `geoask_credentials.py` | Windows DPAPI 或 POSIX `0600` 文件 |
| 分发 | `pyproject.toml`、`setup.py`、`scripts/build_desktop.py` | wheel 与 Windows 目录包 |

网页不保存密钥。密钥留在 Python 进程或用户目录的连接文件里。环境变量优先于已保存的密钥。

## 4. 默认配置

`config.yaml` 固定为高德在线模式：

- `amap.enabled` 与 `amap.primary` 均为 true。关闭其中任一项时，程序会拒绝加载配置。
- `routing.provider` 只能是 `amap`。
- `default_location` 是北京国贸附近的 WGS84 坐标，仅作为地图起点默认值。
- `llm` 默认指向 DeepSeek 的 JSON 模式。密钥不要写进这个文件。

旧配置里的 `geojson_path`、嵌入模型、地名目录、`parking` 和 Valhalla `endpoint` 会被丢掉，不会重新启用本地查询。

## 5. 查询规则

- 一次最多 6 站，顺序与用户说法一致。
- 类别查询使用用户设置的半径，并默认选中最近候选。
- 写明具体地点时，按名称检索，半径放到高德允许的上限；多个候选必须由用户确认。
- “不明确”“未知”“unknown” 这类解析失败不会拿去检索。
- 描述词（例如“安静”）会显示出来，但不会当作筛选条件。
- 停车场是单独的高德关键词检索，只替换驾车路线的最后一点，不改前面的站点。

## 6. 界面与打包

`python geoask_web.py` 打开桌面窗口。`--browser` 使用外部浏览器，`--no-browser` 只启动 `127.0.0.1` 服务。接口、会话令牌和静态文件白名单见 [前端与本地接口说明](web-frontend.md)。

Windows 便携包由 `scripts/build_desktop.py` 用 PyInstaller 生成，包含配置、网页和定位脚本。包内没有 OSM 样本，也没有 DuckDB spatial 扩展或嵌入模型。

安装后的 wheel 通过 `scripts/verify_wheel.py` 检查资源、本机接口和命令行 `--dry-run`。`--dry-run` 只打印将要发送的高德查询说明，不附带 Key，也不访问地点接口。

## 7. 测试

`python -m pytest -q` 覆盖意图解析、高德请求形状、多站选点与路线、停车场终点替换、凭据保存、本机 HTTP 接口和设备定位校验。测试使用假响应，不调用付费接口。
